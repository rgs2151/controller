# linearization_error_explore

## Goal

This folder is the dedicated home for experiments on the linearization error, which in this repository is effectively the residual mismatch between the observed next-layer state and the one-step linear prediction from the frozen dynamics model.

## What is the zeta / linearization error?

The repo’s residual logic measures the gap between:

- the actual next-layer representation, and
- the model’s predicted next-layer representation from local linear dynamics.

The implementation in `robust_steerability/calibration/residuals.py` computes a controller-aware residual based on the one-step model update. In the docs, this mismatch is described as `xi[k]` and as a relative residual norm:

- `||xi[k]|| / ||x[k+1]||`

This is the core quantity behind the “linearization error” story.

In practical terms:

- low residual means the local linear approximation is tracking the real dynamics well;
- large residual means the model is deviating from the local linear prediction, which may indicate nonlinearity, distribution shift, or bad control alignment.

The repo further distinguishes:

- residual magnitude: `||xi||`
- direction-aware effect: how the residual projects into the semantic/control direction
- residual amplification: `|T_LQR xi| / ||xi||`
- semantic failure: how far the actual state drifts from the target behavior

## Recommended experiment questions

- How does the residual grow across layers?
- Does it increase under OOD prompts?
- Is the failure driven by residual magnitude or by residual direction?
- Does the residual correlate with semantic tracking failure more strongly than with raw state norm?

## Working definition to use here

Use “zeta” as a shorthand for the linearization residual / residual mismatch term, i.e. the gap between observed residual dynamics and the local linear prediction generated by the model. For this folder, keep the notation explicit and prefer the term “linearization residual” unless a specific paper or method uses “zeta”.
